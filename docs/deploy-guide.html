Deploy Guide

Follow the steps in order. Tick each box when done. Copy buttons put the command on your clipboard. Paste it into the terminal and press Enter.

0 of 8 steps done
Before you start This builds real resources in the company AWS account <ACCOUNT_ID>, region us-east-1, all named suman-.... It costs pennies while it exists, plus a few cents per document. Step 8 removes everything.
1

Open the terminal in the right folder

In VS Code's file panel, right-click the backend folder and choose Open in Integrated Terminal.

doc_exp_pip_lne/ ├── backend/ <-- right-click THIS one │ ├── app.py (CDK looks for these two files) │ ├── cdk.json │ ├── infra/ │ ├── src/ (not this one, where the agents are) │ └── tests/ ├── frontend/ ├── docs/ └── test_docs/
pwd
You should see/home/suman-manyam/ai_projects/doc_exp_pip_lne/backend
Stop ifthe path ends with anything else (for example /lambdas or no backend). Run cd /home/suman-manyam/ai_projects/doc_exp_pip_lne/backend.
2

Set up the terminal

Load your settings. deploy.env holds your account and profile, and it is never uploaded to GitHub. (First time? Copy deploy.env.example to deploy.env and fill it in.)

source .venv/bin/activate
source deploy.env
You should seenothing printed, and (.venv) at the start of your prompt.
NoteThese settings last only for this terminal window. If you open a new terminal, paste them again.
3

Check which account you are in

aws sts get-caller-identity
You should see"Account": the same 12-digit number as APPROVED_ACCOUNT in your deploy.env
Stop ifthe account number is anything else. Do not continue.
It says the session has expired

Log in again, then repeat this step:

aws sso login --profile <your-aws-profile>
4

Run the tests

Free, and nothing touches AWS. This proves the code still works before you deploy.

pytest -q
You should see61 passed
5

Preview what will be created

cdk diff only shows the plan. It creates nothing.

cdk diff
You should seea list of new things, each marked [+]: 2 DynamoDB tables, 5 Lambda functions, 1 state machine, 1 HTTP API, and IAM roles. Everything is named suman-....
Stop ifyou see [-] or [~] lines (things being deleted or changed), or any name that does not start with suman-.
"cdk: command not found"

Install it once, then run step 5 again:

sudo npm install -g aws-cdk
6

Deploy (this creates the real resources)

Last checkStep 3 showed account <ACCOUNT_ID>, and the plan in step 5 looked right. If both are true, go ahead.
cdk deploy

CDK first shows a table of permissions it will create, then asks:

Do you wish to deploy these changes (y/n)?

Read the table. It should list permissions for the Lambdas, the state machine, and Bedrock (one model only). Then type y and press Enter. It takes a few minutes.

You should see at the end"Deployment time: ..." and an output line like
suman-doc-explainer.ApiUrl = https://abc123.execute-api.us-east-1.amazonaws.com
Copy that URL. You need it in step 7.
It failed with an error

Copy the last 15 lines of the error and send them to me. A half-finished deploy rolls back by itself, and you can run cdk deploy again.

7

Connect your web page and test

  1. Open frontend/index.html in VS Code.
  2. Find this line near the bottom (search for API_URL): 
    const API_URL = "";
  3. Paste your URL between the quotes. No slash at the end. 
    const API_URL = "https://abc123.execute-api.us-east-1.amazonaws.com";
  4. Save the file, then open it in your browser (double-click it, or right-click, Open with Live Server).
  5. Attach a file from the test_docs/input folder, for example sample_lease.txt, and click the arrow button.
You should seethe 3 steps tick off one by one, then the breakdown with risk labels. It takes about 30 to 60 seconds.
Test fileWhat a good result looks like
sample_lease.txtAuto-renewal and early termination flagged high
sample_clean_agreement.txtNothing flagged high
sample_too_long.txtThe page refuses it before sending
Compare with the answersOpen the matching test_docs/result/ans_...md file only after the result is on screen. Never keep it open in the file you upload.
The page says "Could not submit" or nothing happens

Press F12 in the browser and open the Console tab. A red "CORS" or "Failed to fetch" message usually means the URL is wrong or has a slash at the end.

The job shows FAILED

Open the AWS console, region N. Virginia (us-east-1), then Step Functions, then suman-doc-explainer-pipeline, then the latest execution. The red box shows which stage failed. Click it, then open its Lambda log. Send me the error text.

8

Delete everything when you are done

Run this after the demo and after you have your screenshots and audit log. Do it from the same backend terminal (repeat step 2 if you opened a new one).

cdk destroy

Type y when asked. All suman- resources are removed, and so is the data in the tables.

Before you destroySave the audit log first: AWS console, DynamoDB, table suman-audit-log, Explore items. Take a screenshot.
