Document-Explainer Pipeline

Paste a lease or policy, get a plain-English, clause-by-clause breakdown with flagged risks. All AWS resources are named suman-....

How a request flows

  1. The page sends the document to POST /jobs. suman-start-job checks it (not empty, at most 20,000 characters), saves a RUNNING job, starts the state machine, and returns a job_id.
  2. Step Functions runs the three stage Lambdas in order. Each one asks Claude through Bedrock, checks the JSON answer, and writes an audit row.
  3. If a stage fails, it retries up to 3 times. If it still fails, the job is saved as FAILED.
  4. After stage 3, Save result stores SUCCEEDED and the finished result in the jobs table.
  5. Meanwhile the page asks GET /jobs/{job_id} every 3 seconds. suman-get-status returns the status, how many stages have finished (counted from the audit log), and the result when done.

The three stages

StageDoesAdds to each clause
1. clause-extractorSplits the document into numbered clauses, wording copied exactlyclause_id, original_text
2. risk-flaggerRates each clause low, medium or highrisk_level, category, reason
3. plain-english-rewriterExplains each clause simply and adds the disclaimerplain_english

Safety built in

  • Prompts use only the document's text and say "unclear" instead of guessing.
  • Each stage checks the AI's answer. Stage 1 confirms every clause really appears in the document.
  • The AI can't change the original wording, the risk labels, or the disclaimer. Our code adds them.
  • The "not legal advice" disclaimer is added by code to every result.
  • Bedrock permission is limited to one model. The API is throttled to limit cost. Demo only, with no login: use fake documents.

Status: deployed with cdk deploy (stack suman-doc-explainer) and tested (76 local tests, real runs on the deployed stack). The web page is served by a private S3 bucket behind CloudFront. Code layout: backend/src/agents, api, shared.
